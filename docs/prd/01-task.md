## 1. 本域负责什么

| 负责 | 不负责 |
|---|---|
| 任务实体、6 态状态机、迁移守卫 | 消息如何从 IM 进来（→ 02-im） |
| 提醒**语义**（何时该提醒、提醒什么、升级曲线） | 提醒**投递**（通道、模板、载体 → 02-im） |
| 看板、视图分组、任务工作区 | IM 侧的锚定、白名单、安全（→ 02-im） |
| 复盘（日终/周）与任务域统计 | 模型选择、token 计费策略（→ 02-runtime） |

**归属原则**：凡是"这条任务现在算什么状态、该不该提醒、提醒说些什么"，都在本域；凡是"这句话怎么送到用户手机上、用户怎么点回来"，都在 02-im。两边以 §9 的接口契约对接。

## 2. 数据模型

### 2.1 Task

| 字段 | 说明 | 必填 |
|---|---|---|
| `id` / `short_code` | 内部 ID / 人读短码（`T-7F3`，IM 显式指定用） | ✓ |
| `title` | 一句话标题（≤ 40 字） | ✓ |
| `raw_input` | 原始输入（原话/邮件片段/语音转写），**永不丢弃** | ✓ |
| `status` | `todo` / `doing` / `blocked` / `paused` / `done` / `canceled` | ✓ |
| `due_at` | 截止时间（可空 = 无期限池）；精度支持"日"/"时分" | |
| `priority` / `estimate` | P0–P3（默认 P2）/ 预估分钟 | ✓ / |
| `source` | `manual` / `im` / `email` / `meeting` / `voice` / `ai_split` | ✓ |
| `people` | `{role: owner\|waiting_on\|waiting_for, name}` | |
| `project` / `parent_id` | 项目标签 / 父任务 | |
| `defer_until` | 推迟到某时间点再现；**只作用于 `todo`** | |
| `waiting_since` | 进入 `blocked` 的时间（算等待天数） | `blocked` 时 ✓ |
| `paused_at` / `pause_reason` | 进入 `paused` 的时间 / 原因枚举 | `paused` 时 ✓ |
| `progress_note` | **做到哪了**（1 行）；已有 run/产物时进入 `paused` 必填 | 见左 |
| `resume_when` / `pause_rounds` | 复活条件（自由文本，可空）/ 搁置轮次 | |
| `resume_check_at` | 下次回访时间（`paused_at + 节奏` 派生，不手工填） | |
| `thread_id` | 会话线程（一任务一线程，桌面与 IM 共用） | ✓ |
| `created_at` / `updated_at` / `done_at` | 时间戳 | ✓ |

`pause_reason` 枚举：`wait_timing`（等时机）/ `missing_input`（缺前置）/ `deprioritized`（降优先级）/ `low_energy`（精力）/ `external_change`（外部变更）/ `other`。

**关键约束**：`raw_input` 永久保留，任何 AI 提炼都能回溯到原话——这是"AI 不乱记"的信任基础。

### 2.2 TaskRun

| 字段 | 说明 |
|---|---|
| `id` / `task_id` / `thread_id` | 归属 |
| `status` | `queued` / `running` / `waiting_approval` / `succeeded` / `failed` / `canceled` |
| `trigger` | `desktop` / `im` / `schedule` / `rule` |
| `budget` / `summary` / `artifacts` | token 与时长上限 / 一句话摘要 / 产物清单 |

**规则**

1. 同一任务同一时刻只有 1 个 `running`；**v1 跨任务串行（并发 = 1）**，多任务并发与排队可视化列为 M2+。
2. `run 成功 ≠ 任务完成`：交付草稿后仍需人确认。
3. `waiting_approval` 是常态：写操作挂起等审批，超时默认拒绝。
4. `todo` 发起 run → 自动转 `doing`；`blocked` / `paused` 不自动起 run。
5. 用户可随时中断，产物保留，任务回到 `doing`。
6. 复活 `paused` 时，`progress_note` 与最近产物置顶首屏。

### 2.3 两个易混淆字段：`project` 与 `parent_id`

两者都用于"把任务归到一起"，但归的是**不同的东西**：`project` 是横向归类（同一客户/项目），`parent_id` 是纵向拆解（一件事的步骤）。都可空，不违反"零必填"。

#### `project`：字符串标签，不是领域实体

**作用（三处，缺了就不需要这个字段）**

| 用途 | 说明 |
|---|---|
| 筛选 | 看板按项目/客户过滤；"这个客户的 8 件事现在什么状态" |
| 聚合 | 周报、复盘按项目出工作量（画像是 C 的核心诉求） |
| AI 上下文 | 同项目的任务共享一批背景（术语、对接人、交付物格式），作为轻量提示注入 |

**为什么是字符串而不是一张 `projects` 表**：一旦建实体，就要有项目状态、成员、权限、归档——那是团队协作软件的路，属明确非目标（总纲 §3）。字符串足够表达"归到哪一类"。

**已知代价与对策**

| 代价 | 对策 |
|---|---|
| 拼写不一致（"华东项目"/"华东") | 输入时自动补全最近使用；提供"合并标签"操作 |
| 改名要回填 | 本地 SQLite，批量更新成本低；改名时一并更新历史（保留别名映射） |
| 一个人可能想多标签 | 首版只允许一个 `project`；确实需要时用 `#tag` 写进标题，不做多值字段 |

#### `parent_id`：一层拆解，不是任务树

**作用**

| 用途 | 说明 |
|---|---|
| 承载 AI 拆解 | "整理资质 → 补充报价 → 内部过审"是**一条任务的三个步骤**，不是三条独立待办 |
| 防任务爆炸 | 拆解结果折叠在父卡片内，不污染主看板（否则建一条任务变四条，用户立刻弃用） |
| 分别排期 | 子任务可各自有 `due_at` / `estimate`，父任务只做汇总 |

**四条硬规则（此前未定义，现补）**

1. **只允许一层**：父任务不能有父（`parent_id` 指向的任务其 `parent_id` 必须为空）。多层树会让状态汇总、看板分组、时间估算全部复杂化，收益极低。
2. **子任务各有独立线程，但不从零开始**：子任务也是任务，按公理一必须有自己的一条线程（点进去能看到"这一步"的完整对话与产物）。它与父线程的关系是**单向继承 + 摘要回写**：
   - 继承：子任务上下文自动带上父任务目标、共享文件与人，以及兄弟子任务的一行列表（只给标题与状态，**不给全文**）；
   - 回写：子任务的关键事件（状态变更、run 完成摘要）以一行系统消息汇总进父线程，**不复制全文**（避免父线程 token 爆炸与串味）；
   - 提升：若某子任务实际是独立的一件事（换了人、换了交付物），执行**提升**——脱离 `parent_id` 成为顶层任务，线程原样保留。
3. **父子状态不自动联动**：子任务全完成 → 父任务只是**提示**"可以收尾了"，不自动 `done`（延续 §3.3 规则 4）。父任务卡片显示进度 `2/3`，但不替用户改状态。
4. **父完成时子任务不能静默遗留**：若仍有未完成子任务，弹三选一——`全部标记完成` / `级联取消` / `保留（父完成、子任务继续）`。默认不选，避免"父完成了但里面还有活"。
5. **拆解规模有边界**：子任务 < 2 就别拆（直接做）；> 7 说明这已经不是"一件事"，提示"要不要拆成多个独立任务"。经验区间 **3–7 个**。

**看板与提醒**：子任务默认折叠在父卡片内，不进主列表；但子任务**自己的 `due_at` 照样触发提醒**（提醒挂在子任务上，文案带父任务标题做上下文）。

## 3. 状态机（6 态）

```
                    ┌──────────────── 重开 ────────────────┐
                    ▼                                       │
              ┌──────────┐   开始    ┌──────────┐   完成   ┌──────┐
        ┌────▶│   todo   │─────────▶│  doing   │────────▶│ done │
        │     └────┬─────┘          └────┬─────┘         └──────┘
        │          │ 完成(直接)            │ 取消
        │          │                      ▼
        │          │                ┌───────────┐
        │          └───────────────▶│ canceled  │
        │                           └───────────┘
        │                                ▲   ▲
        │  等外部      ┌──────────┐      │   │
        ├────────────▶│ blocked  │──────┘   │
        │  ◀───解除────│          │──────────┐
        │              └────┬─────┘          │
        │   转等待  ┌───────▼──────┐  放弃  │
        └──────────│    paused    │────────┘
          改期/继续 └──────────────┘
```

| 状态 | 语义 | 必填 | 视图位置 | 提醒曲线 |
|---|---|---|---|---|
| `todo` | 待办，还没开始 | — | 今天、本周 | 截止前（`due` 驱动） |
| `doing` | 进行中，在我手上 | — | 今天 | 到期 + 停滞追问 |
| `blocked` | 等待中，卡在外部 | `waiting_on` + `waiting_since` | 今天（阻塞提示） | **递增** 2 → 3 → 5 → 7 天 |
| `paused` | 搁置中，主动放下 | `pause_reason` + `paused_at`（有进展加 `progress_note`） | 仅复盘，看板折叠 | **递减** 3 → 7 → 14 → 30 天 |
| `done` | 已完成 | — | 折叠 | 不提醒 |
| `canceled` | 已取消 | 取消原因（可选） | 折叠 | 不提醒 |

**派生视图「推迟」**：`todo` + `defer_until` 非空。有明确再见日期，到点自动回待办池，不占状态枚举。这是 `paused` 的对照物——**有日期用 defer，没日期用 paused**。

### 3.1 转移矩阵

| 从 \ 到 | `todo` | `doing` | `blocked` | `paused` | `done` | `canceled` |
|---|---|---|---|---|---|---|
| `todo` | — | ✔ 开始 | ✔ 没开工就卡住 | ✔ 没日期地放着 | ✔ 直接完成 | ✔ |
| `doing` | ✔ 撤销开始 | — | ✔ 等别人 | ✔ 先放着 | ✔ | ✔ |
| `blocked` | ✔ 不需要等了 | ✔ 对方给了 | — | ✔ 不再等，先放着 | ✔ 等的东西到了且事已毕 | ✔ |
| `paused` | ✔ 改期（可配 `defer_until`） | ✔ 继续 | ✔ 转等待 | — | — | ✔ 放弃 |
| `done` | ✔ 重开 | — | — | — | — | — |
| `canceled` | ✔ 恢复 | — | — | — | — | — |

**禁止项及理由**

1. `done → doing`：重开必须落 `todo`，强制人再确认一次。
2. `paused → done`：搁置的事不会自己完成，要么继续要么取消。
3. `canceled → done/doing`：恢复只能回 `todo`，避免"取消了又算完成"污染完成率。

**守卫落点**：矩阵校验在 `task-core` 领域层实现，桌面 UI 与 IM 通道都**不能绕过**（IM 只是发起方，合法性由领域层裁决）。

### 3.2 为什么最终选 6 态（D5 / D10 改判记录）

v0.2–v0.3 曾用"字段 + 派生视图"表达等待与搁置，后改判为显式状态：

| 维度 | 字段派生（旧） | 显式状态（现） |
|---|---|---|
| 实现 | 视图与提醒各写一遍派生逻辑，两处必须一致 | 按 `status` 过滤，一处真相 |
| 一致性 | `doing && waiting_on` 与 `doing && paused_at` 可能同时成立 | 状态互斥，天然不叠加 |
| 用户认知 | 状态栏只显示"进行中"，靠徽标解释 | 看板列即真相 |
| IM 交互 | IM 只能显示"进行中"，"先放着"要猜落哪个字段 | 六态短标签，指令与状态一一对应 |
| 统计 | 聚合要写派生 SQL | 直接按状态统计 |
| 代价 | 零额外操作 | **多一次手选** |

**抵消手选成本的五条**（缺一条状态就会乱）：

1. AI 建议 + 一键确认（原话 → 状态，见 §4 用词表）。
2. 自动迁移：`todo` 起 run → `doing`；`blocked` 的等待对象有回复 → 提示转 `doing`。
3. 键盘/拖拽：`1/2/3/4` 或拖到列，不弹必填表单。
4. 每列一个头号动作：`blocked` 列是"催办"，`paused` 列是"继续"。
5. IM 里一句话即切（"先放着"→ `paused`，归属见 02-im §4）。

### 3.3 规则

1. 状态变更只能由人确认（或人授权后由规则/AI 变更）；AI 只有建议权。
2. `blocked` 必须有 `waiting_on`；`paused` 必须有 `pause_reason`；缺字段不允许进入（引导补齐，不阻塞对话）。
3. `canceled` 不计入完成率，可恢复为 `todo`。
4. 子任务全完成 → 父任务提示"可以收尾了"，不自动 `done`。
5. 等待/搁置都不删任何东西：线程、产物、进度冻结保留，复活即续。
6. 所有变更写 `task.status_changed{from, to, actor, channel, reason}`，`channel ∈ {desktop, im, rule}`，可回放。

## 4. `blocked` 与 `paused` 的判据

| 维度 | `blocked` 等待中 | `paused` 搁置中 |
|---|---|---|
| 卡点 | **外部**：别人 / 外部条件 | **内部**：自己的决定 |
| 控制权 | 不在我手上，被动 | 在我手上，主动 |
| 一句话判据 | "**我不能推进**" | "**我选择先不推进**" |
| 下一步动作 | 对外：催办 / 换方案 / 降级 / 上报 | 对内：继续 / 改期 / 转等待 / 封存 |
| 提醒曲线 | **递增**（越久越急） | **递减**（越久越静） |
| 提醒语气 | "该催了" | "还要吗" |
| 出现位置 | 今日视图（阻塞提示） | 仅复盘；看板折叠 |
| 报表含义 | 协作健康度：我被谁卡住 | 堆积债务：我欠自己多少 |

**AI 判定用词表**（桌面与 IM 共用）

| 原话片段 | 建议状态 |
|---|---|
| "等 X 回我" / "等审批" / "对方还没给" | `blocked`（`waiting_on` = X） |
| "先放着" / "不急" / "过阵子再说" / "等时机" | `paused`（`pause_reason` = `wait_timing` 等） |
| "下周再说" / "周五以后再弄" | `todo` + `defer_until` |

**同时像两者时**（既等客户给数据，自己也腾不出手）：判 `paused` —— 不催别人，先问你要不要继续。宁可少一次催办，不要多一次误催。

**为什么曲线相反**：等待的成本随时间线性增长（项目卡越久代价越大），压力必须递增；搁置的成本已沉没（越催越焦虑也无益），打扰递减——但每 30 天强制清点一次防遗忘。

## 5. 提醒语义（只管"该不该说、说什么"）

投递通道、消息模板、交互载体见 02-im §5–§9。

### 5.1 触发点

| `slot` | 触发 | 适用 |
|---|---|---|
| `due-1d` / `due-2h` / `due-30m` / `on-due` | 按 `due_at` 前推 | `todo`（有 due）/ `doing` |
| `overdue-1d` | 逾期次日 | `todo` / `doing` |
| `waiting-N` | 第 N 次升级（2/3/5/7 天） | `blocked` |
| `resume-check-N` | 第 N 轮回访（3/7/14/30 天） | `paused` |
| 自定义绝对时间 | 用户指定 | 任意 |

幂等键 = `task_id + slot`，唯一索引，重启不重发。

### 5.2 提醒内容语义

| 状态 | 说什么 | 该给的下一步（由 02-im 渲染成按钮/编号） |
|---|---|---|
| `todo` | 到期/逾期 N 天 | 完成 / 改期 / 打开 |
| `doing` | 距截止 N 分钟；停滞 N 小时 | 完成 / 搁置 / 打开 |
| `blocked` | 在等 X 已 N 天 | 催办 / 转进行中 / 转搁置 / 改期 |
| `paused` | 搁置 N 天，上次停在… | 继续 / 改期 / 转等待 / 取消 |

### 5.3 节奏与预算

1. **`blocked` 递增**：2 → 3 → 5 → 7 天，每轮只问"还需要等吗 / 要不要催"。
2. **`paused` 递减**：3 → 7 → 14 → 30 天，**只并入日终/周复盘，不单独弹窗**；搁置任务不参与到期轰炸。
3. **封存判定**：连续 3 次"继续搁置"且 `resume_when` 为空，或搁置 > 90 天 → 复盘建议取消（保留可查）。
4. **防疲劳**：单日推送上限默认 8 条，超限合并；连续忽略 3 次同类 → 自动降频并询问"要不要改期"。
5. **静默**：22:00–08:00 不推，顺延次日 08:30 合并为一条。
6. **离线补偿**：启动时合并推送"错过的 N 条"，不逐条轰炸。

## 6. 看板与视图

- 视图：**今天**（`todo` 到期 + `doing` + `blocked`）/ **本周** / **全部** / **搁置中**（默认折叠，绝不占"今天"）
- 列：待办 · 进行中 · 等待中 · 搁置中 · 已完成（折叠）· 已取消（折叠）
- 卡片：**标题 + 创建时间**（列位置即状态；短码、截止、优先级移到悬停提示与任务详情，卡片不做信息堆叠）；有 run 在跑时以角标提示
- 列头聚合（替代卡片徽标）：每列显示条数与最长天数，如「等待中 · 3 件，最长 5 天」「搁置中 · 2 件，最长 12 天」——保住"谁在等我"的信息密度，又不挤占卡片
- 支持按项目/人筛选；**不做**自定义字段与多视图配置（首版拒绝配置化陷阱）
- 空状态引导："试试转发一条消息给我"

## 7. 任务工作区（一任务一线程）

| 能力 | 说明 | 验收 |
|---|---|---|
| 任务线程 | 打开即恢复完整上下文（原话、关联文件/邮件、历史 run 摘要） | ≤ 300ms；切任务完全隔离 |
| **父子视图** | 父任务页显示进度 `n/m` + 子任务列表（每行：标题、状态徽标、截止、一行摘要）；点子任务进入其独立工作区，面包屑一键返回父 | 父→子点击 ≤ 1 次；返回不丢父页位置 |
| IM 汇入 | IM 里对该任务说的话追加进同一线程并标注渠道 | 桌面端切换即见，无第二套历史 |
| 执行与产物 | 起草、查资料、改文件、拆子任务；产物落到**工作空间**并挂任务下 | 每次执行有可见产物条目 |
| 执行状态 | 排队/运行中/等审批/已完成/失败（v1 串行，同一时刻最多 1 个 run） | 后台跑，切回可见进度 |
| 审批内联 | **命令审核模块判为需审批的命令**（读 / 写 / 删 / 执行一视同仁，判定在规则库）弹审批卡片；任务侧不自定义规则 | 审批不跳出上下文 |
| 工作空间 | 右侧文件树，指向真实本地文件夹；产物直接落在该目录，改动文件在树中标记"已变更"，点击查看内容 | 产物一次点击可达 |
| 变更留痕 | 写文件记入线程事件流（工具、路径、增删行数），轨迹中可回看 | 任一文件改动可追溯到 run |
| 状态条 | 顶部六态一键切换 + AI 建议 | ≤ 2 次操作 |
| 搁置与复活 | 冻结现状；复活首屏给"上次停在…"+ 产物 | 复活后 30s 内可继续 |
| 轨迹折叠 / 归档 | 工具调用默认折叠；完成后只读，可重开 | 归档后不可改 |

**红线**

1. 全局只有一个"快速问答"入口：无归属、不落产物、不建线程；说"记一下"立即转任务。
2. 禁止隐式跨任务携带上下文；引用他任务必须显式，且只注入摘要。
3. 长内容（长文、diff、产物全文）只在桌面端呈现。

## 8. 复盘与任务域指标

### 8.1 复盘

- **日终**（18:30 可配）：今日完成 N / 等待中 M / 搁置 K（最长 N 天）/ 明日 Top3；一键生成日报文本；未完成项问"顺延到明天？"

| 指标 | 目标 |
|---|---|
| 状态新鲜度（24h 内被推进或确认） | ≥ 80% |
| 状态建议采纳率 | ≥ 85% |

| 搁置 > 90 天仍无处置 | 持续下降 |

| AI 越权改状态次数 | **0** |
