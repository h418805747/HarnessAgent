## 缺失清单（M1 必须做但没有工作项）

按依赖顺序，这 8 项构成一条必须补的链：

```
3.9  内核（Container / EventBus）
  └─ 3.5  session 事件流（append-only + resume）
       └─ 3.4  单库持久化（task/thread/reminder/audit）
            └─ 3.3  worker（Runtime 循环）
                 └─ 3.2  服务（注册表 + ensure + 路由）
                      └─ 3.1  Electron 壳（窗口/托盘/热键/IPC）
  └─ 3.8  技能加载器（status-infer 依赖）
  └─ 3.6  命令审核模块（IM 审批依赖；规则库内容后议）
  └─ 3.11 配置分层 + profile
  └─ 3.10 审计留痕
```

## M1 收敛结果（已采纳路径 A）

M1 用**单进程**实现，不做服务/worker 拆分。四项基础设施已并入 `M1.md` §3：

| 新工作流 | 内容 | 估时 | 覆盖缺失项 |
|---|---|---|---|
| W0 内核最小版 | Container + EventBus + Logger + 配置分层 | 0.5 周 | 3.9、3.10、3.11 |
| W1′ session 最小版 | 单库初始化 + append-only 事件表 + `resume` | 0.5 周 | 3.4、3.5 |
| W9 壳骨架 | Electron 主进程 + 单窗口 + 热键 + IPC 桥（托盘/通知移 M1.5） | 0.75 周 | 3.1 |
| W10 技能加载器最小版 | `SKILL.md` 解析 + 目录扫描（并入 W2） | 0.25 周 | 3.8 |

接口仍按 `10-control-plane` 的 `IEnvelope` / `ensure` 语义写，M2 拆双进程时业务代码不重写。

**周期结论**：原 W1–W8 合计 9.5 周已超 8 周预算；加 2 周基础设施后为 11.5 周，通过把钉钉 / ClawBot / 托盘与通知 / 剪贴板入口移 **M1.5** 压到 **10 周**。M1 周期由 8 周修订为 10 周。

**仍未进 M1 的缺失项**：3.2 服务进程、3.3 worker 进程（按路径 A 有意推迟到 M2）、3.6 命令审核模块（规则库讨论后再定）。

**排期结果**：原先 6 项未排期已全部归入 M2——语音捕获进 **M2a**，页面能力（4.1–4.3）、记忆/工具、git/diff、并发、导出导入进 **M2b**。M3「委托执行」的前提因此具备，**未排期归零**。

**M2b 的容量提醒**：8 周内要装下 6 个能力项，实际估算约 8–10 周。若需压缩，建议把「全量导出/导入」与「多任务并发」后置到 M3 之后（两者都不阻塞任何其他功能），页面能力与记忆/工具不可压缩——它们是委托执行的前置。
